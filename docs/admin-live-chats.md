# Admin live chat viewer

Approved scope: read-only viewing of currently open Hermes registration and website-details conversations. Admins cannot take over or send messages. Fixed-questionnaire/fallback chat transcripts are not stored server-side and are explicitly excluded in the UI.

Admin navigation has Active Chats at the configured admin path plus `/chats`. Supplier details link to a supplier-filtered view. Before registration confirmation a visitor may have no supplier record; these sessions remain visible in the general list. Names are accepted draft data, not verified identity.

The page polls the authenticated `/chats/feed` endpoint every 3 seconds, sequentially, with a 10-second network timeout. Hidden admin tabs pause polling. The endpoint returns up to 50 recently active sessions and at most 200 messages in the selected active conversation. Client text is rendered as text, never HTML. API responses omit public chat capabilities, invite tokens, full answers, and settings. No public viewing endpoint or reply endpoint is added.

Open means status `open`, inside the existing 24-hour chat lifetime, and a browser check-in in the last 90 seconds. Supplier polling records presence at most once every 20 seconds. Closing a browser can therefore take up to about 90 seconds to disappear. Review, done, fallback, expired and disconnected sessions are omitted from both the list and selected transcript. Admin polling cannot keep a client session open and does not touch messages, answers or Hermes leases. Closed transcripts remain in existing storage but this feature provides no history viewer or deletion policy.

Deployment requires the new migration `2026_11_11_000001_add_browser_presence_to_agent_chats`, which adds nullable indexed `agent_chats.last_seen_at`. Existing conversations become visible on their next browser poll. Apply the migration with the release before serving the updated application. No seeders or local database imports are required for this feature. Preserve production `.env`, APP_KEY, uploads and cPanel PHP settings. The previously prepared question-definition changes remain a separate production step.

Validation: full PHP suite at the initial implementation: 301 tests / 2,897 assertions. Two further live-chat tests were added and the final 6-test feature suite passed (41 assertions). Twelve frontend tests and Vite build passed. Independent review found no blocking defects; its fetch-timeout suggestion was implemented. An isolated test-database browser run verified authenticated viewing, message arrival without reload, timestamps, 393px layout without overflow, absence of a composer, and transcript/list removal when the session ended. QA server stopped and dummy account/chat removed. Production behavior remains unverified until rollout.
