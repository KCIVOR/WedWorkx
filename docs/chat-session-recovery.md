# Chat session recovery

Bot 2 starts are now invitation-based: after checking the invitation remains editable, the server locks the supplier row and reuses its latest open/review chat within the existing 24-hour lifetime. Browser tab session storage is no longer the only recovery mechanism. Existing messages, accepted answers and the upload widget remain attached to the same chat. Reconnection is allowed even when Hermes temporarily lacks a fresh heartbeat; genuinely new chats still require it. The invitation remains a private capability and must not be shared publicly.

Bot 1 uses an encrypted HttpOnly SameSite=Lax cookie, scoped to the browser and limited to the chat lifetime. A legacy sessionStorage id can be supplied during start to migrate an existing tab's session into the cookie. Only open/review registration chats without a supplier record can be resumed by this path. Cross-browser/device Bot 1 recovery is not provided by a cookie; a separate continuation-link feature would be required. System mode, closed/expired chats and locked/paid website details still retain their existing restrictions.

Server resume availability takes precedence over a stale fixed-questionnaire draft. Confirmed website answers are not restarted. The fixed flow offers Try AI chat; its existing page draft remains in memory. The transport now retries starts three times, retries six failed/invalid polls, times out individual requests after ten seconds, and caches accepted answers for a network fallback. Explicit retry clears the old accepted cache so a failed restart cannot overwrite corrected fixed-form data. A fifteen-second reply grace window allows short browser handoffs before requesting fallback. Reconnection locks and re-reads chat state to avoid overwriting a concurrent agent reply's cleared waiting flag.

This release adds no migration, dependency, plugin change or cPanel timezone setting. Deploy matching PHP, React bundle and manifest, then clear Laravel caches. Existing clients should reload. Registration cookie recovery requires cookies to be allowed. Browser privacy settings can prevent it; Bot 2 instead identifies the conversation by invitation.

Regression coverage includes invitation reuse with no browser storage and stale Hermes heartbeat; transcript/accepted-answer preservation; registration cookie reuse and review; mode/paid-lock enforcement; stale-model concurrent reply handling; frontend draft-versus-resume rules; confirmed-answer protection; reply grace; and malformed-response validation. Physical phone email-app-to-Chrome behavior should be checked after production rollout.
